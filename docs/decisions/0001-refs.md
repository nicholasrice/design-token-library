# 1. Token values are data, and a reference is a ref

Status: proposed (2026-10-26)

## Context

Any function in a token value was an alias: `$value: (tokens) => tokens.a`, and a function at any depth of a value was called with the library's tokens. One rule did several jobs, and it caused these problems:

- **A value couldn't be told apart from an alias.** To find aliases, a value was rebuilt as a plain object, so a class instance, a `Date` or a `Map` lost its prototype and internal state, and a function property of it was called (#55). Walking only plain data (#57) keeps the instance, but a function inside plain data is still called.
- **The types could promise a value the runtime didn't return.** A class whose method has the shape of an alias type-checks, and its token resolves to `undefined` or to a function.
- **Nothing could be serialized.** A function doesn't keep the token it refers to.
- **The alias function's argument was hard to type.** It was given the library's tokens, and that type broke down for libraries whose shape is extended or generic (#60, #67, #68).

## Decision

A token's value, at any depth, is a value, a ref, or plain data containing either. A function is never a ref.

- **Two notations, one ref.** `ref("colors.primary")` names a token by its dotted path, and `refs<Theme>()` makes a ref for each token of a shape, `$.colors.primary`. Both make the same data, `{ [REF]: ["colors", "primary"] }`, which is DTCG's `"{colors.primary}"` and can be written to a document as that. "Ref" over "alias": DTCG uses both words, and a ref also reads right as the argument of a recipe.
- **Typed by where it's used.** A ref's type is `Library.Ref<V, TokenValues<R>>`, where `V` is the token's value type. The phantom field `[RESOLVES]?: (library: T) => V` carries both types, and it's never set. `ref(path)` infers `V` and the library from its position, and its path must be one of `TokenPath<T, V>`: the dotted paths of the tokens whose value is a `V`. So a mistyped path or a token of the wrong type is a compile error, also where a string is expected, as in a font family. `TokenValues` marks each token with the type-only `TokenValue<V>`, so a path stops at a token rather than going into its value. Comparing libraries by their token values, rather than their shapes, lets a ref be given to a library with a declared, extended (`Root extends Needs`) or inferred shape. An inferred shape contains the config's own refs, so it would never match by shape.
- **Resolution.** A ref is replaced by its token's value. Plain data is an array that isn't a subclass of `Array`, or an object whose prototype chain has at most one link: an object literal from any realm, or `Object.create(null)`. It's copied from its own properties, including symbol-keyed and non-enumerable ones, with its refs resolved. An object that appears twice in a value, or contains itself, has one copy. A getter on plain data is read once into a data property, because a resolved value is data. Anything else is returned as it is.
- **Copies, not the config's objects.** A token's value is always a new copy of plain data, even with no refs in it, so that values can be frozen (#24, #71) without freezing the config. The proposal returned plain data with no refs by reference; this follows #71 instead.
- **Nothing fails silently.** A ref inside a value that isn't plain data, such as a class instance, would be returned unresolved, so it throws a `TypeError` naming the token and the class. The check reads only data properties, so no getter is called. A path that isn't a token throws when the token is read. A function given as a token's `$value`, in a config, to `set()` or to `extend()`, is a type error, and throws naming the token. `Token.set()` takes the same values as a config.
- **Identification.** `REF` is the registered symbol `Symbol.for("design-token-library.ref")`, checked with `Object.hasOwn`, so a ref made by another copy of the package is still a ref, and a value can't have one by accident. It isn't exported.

## Consequences

- **Breaking.** `$value: (tokens) => tokens.a` becomes `$value: ref("a")` or `$value: $.a`. `Library.Context`, `ValueAlias`, `Alias`, `ValueSource` and `DeepAlias` are removed.
- **No calculations until recipes** ([0003](0003-recipes.md)). A value computed from tokens needs a recipe. This decision is only about references.
- **A shape that is being inferred can't check a path.** In `Library.create({ ... })` without a type argument, or for a new token in `extend()`, `ref(path)` is a type error. The shape is given as a type argument, or the ref comes from `refs<Shape>()`.
- **The contents of a `Map` or a `Set` aren't searched.** They aren't own properties, so a ref in them isn't found by the check, and is returned unresolved.
- **Compile time grows with the number of paths.** `TokenPath` is a union of every path of a type. This hasn't been measured on a library with thousands of tokens.
- Two assertions stand in for what TypeScript can't express. `refs()` returns its proxy as `Refs<T>`, because a type can't describe a proxy's dynamic keys. The library treats a resolved value as its token's value type, which the config's types guarantee.

## Alternatives considered

- **A branded `alias((tokens) => …)` function.** It hides its target from serialization, and it's a second way to write a reference.
- **Return plain data with no refs by reference**, as the proposal did. It keeps the config's objects, but freezing the value would freeze the config.
- **An index-signature guard against class instances in the types.** It's defeated by assigning the instance to a plain-object type first, and it rejects interfaces. The runtime check is the guarantee.
- **Wrapping every composite value** (`composite({ … })`) so the types can tell plain data from an instance. It closes the gap at compile time, at the cost of a wrapper on most values.
- **A string key, or `instanceof`.** A key could collide with a value's property, and `instanceof` fails across copies of the package.

## Not done

- Serialization: a ref is written as `"{path}"`. The `feat/dtcg-json` branch has a JSON-first design to start from.
